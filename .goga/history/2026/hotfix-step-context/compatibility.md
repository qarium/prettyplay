## Verdict

**BREAKING** — failed: Semantic/Same-arguments-same-behavior, Algorithmic/Manifest-guarantees, Consumer/Existing-tests, Consumer/Downstream-caches.

## Owner Approval

Approved 2026-10-11 via the hotfix dialog (q2): the owner quoted the change plan in full — including the runtime removal of `_step_inputs`/`bind_step_inputs`, the five call sites, the manifest annotation, the docs, the three rewritten tests and the example-cache purge — and added one amendment to the prompt wording: the prompt must not be aware that a context exists at all; for the LLM nothing changes — the step is a ready instruction. Amendment applied: the generation prompt rule states only that every value comes from the STEP sentence; no mention of context, globals or their absence anywhere in the prompts; no safety-core addition. The stop is lifted.

## Breaking Change Details

1. **Behavior of context-reading step code.** The only behavior that changes is code that reads the `step_inputs` execution context — the exact construct the owner reported as absolutely unacceptable. It changes from working (by binding a hidden runtime global) to failing loudly with `NameError`, then regenerating under the self-containment prompt through the existing healing loop; strict replays require the documented cache purge. No other call pattern changes behavior.
2. **Manifest guarantee swap.** Engine CODEMANIFEST :147 currently guarantees the context global; the replacement guarantees self-contained code. The old guarantee is the defect carrier — preserving it contradicts the owner's requirement and the shipped addressing contract.
3. **Test and cache consumers.** Three tests are rewritten to pin the new contract; legacy caches need the purge note already present in the docs from the addressing upgrade.

Per policy: the pipeline halts here. Escalation report follows; only the owner can approve proceeding.
