# Юзабилити prettyplay: красивый отказ, вердикты LLM, скриншоты, headless и каналы, доскроллы

## Current State

Текущее состояние библиотеки (факты собраны на technical discovery по коду реализации):

1. **Некрасивый отказ.** `ProductDefectError` не наследует `AssertionError` — unittest/pytest показывают законно проваленную проверку как ERROR с трейсбеком по внутренностям библиотеки вместо FAILED с короткой причиной; трейсбек не сворачивается до границы библиотеки.
2. **LLM-ценность теряется на падениях.** Объяснение и рекомендация вердикта классификации не попадают ни в сообщение исключения, ни в хуки, ни в лог: на пути лечения `recommendation` обрезается у `ProductDefectError`; при исчерпании лечения после rot вердикт теряется целиком; на пути падения генерации классификация не вызывается вовсе.
3. **Маскировка дефекта.** Первый прогон законно падающего assertion-шага сжигает бюджет генерации (по умолчанию 3 LLM-запроса) и падает как `IncurableStepError` — реальный дефект продукта невидим.
4. **Нет скриншотов у автора теста.** `PrettyTest` не умеет получить или сохранить PNG для отчёта; внутренний `PageFacade.screenshot()` существует только как вход LLM.
5. **Настройки «просто не работают».** `headless` не настраивается вовсе (`launch()` вызывается без него), `browser = "chrome"` падает как невалидное значение, env-переменная браузера называется `PRETTYPLAY_BROWSER`, невалидная конфигурация выдаёт сырой `pydantic.ValidationError` вместо обещанной документацией действенной ошибки.
6. **Нет доскроллов.** В фасаде страницы скролла нет вообще; автопрокрутка Playwright срабатывает только как часть действий.

## Description

Реализовать семь принятых решений ADR топика `more-usability` (`.goga/history/2026/more-usability/adr.md`) в существующих ячейках prettyplay — единый юзабилити-выпуск:

- **ADR-1.** `ProductDefectError` наследует и `PrettyplayError`, и `AssertionError` (множественное наследование); сообщение начинается с причины; трейсбек сворачивается до библиотечной границы. Раннеры показывают провал проверки как failure, фасад остаётся framework-агностичным.
- **ADR-2.** Единый вердикт «категория (где применимо) + объяснение + рекомендация» на каждом терминальном отказе шага (`ProductDefectError`, `IncurableStepError`): целиком в сообщение исключения, в новое событие хуков (для отчётов интеграторов) и в лог. Объяснение строится по свежему состоянию страницы; при недоступности LLM — тихий пропуск с WARNING, основной отказ не искажается и не задерживается. На путях с существующей классификацией вердикт переиспользуется, на путях без неё — запрашивается. Чинит потерю `recommendation` у `ProductDefectError` и потерю вердикта при исчерпании лечения после rot.
- **ADR-3.** Провал проверки кандидата при генерации (Playwright `expect_*` поднимает `AssertionError`, типово отличимо от «элемент не найден») останавливает ретраи и переводит шаг на классификацию LLM: вердикт `product_defect` поднимает `ProductDefectError` с объяснением, прочие вердикты — `IncurableStepError` с объяснением и рекомендацией. Не-`AssertionError` ошибки кандидатов ретраяются как сегодня.
- **ADR-4.** Основной объект получает две способности: `get_screenshot` — PNG-байты текущего состояния (full-page) — и `save_screenshot(filepath)` — запись PNG по явно указанному пользователем пути, без привязки к каталогу. Автоскриншотов при терминальном падении шага нет.
- **ADR-5.** Настройка `headless` (TOML-ключ `[tool.prettyplay]`, по умолчанию `true`, env `PRETTYPLAY_BROWSER_HEADLESS`); допустимые значения `browser` расширяются до `{chromium, firefox, webkit, chrome, msedge}` — последние два запускают установленный браузер через механизм Playwright channel. Env-переменная браузера переименована чисто: `PRETTYPLAY_BROWSER` → `PRETTYPLAY_BROWSER_NAME`, старое имя перестаёт действовать, при встрече — подсказка нового.
- **ADR-6.** Ошибки валидации настроек оборачиваются в громкую действенную ошибку библиотеки: имя настройки, полученное значение, список допустимых значений; исходный `ValidationError` остаётся сцепленным.
- **ADR-7.** Фасад страницы расширяется скроллами: страничные — прокрутка к элементу, на величину вниз/вверх, до конца/начала страницы; контейнерные (карусели) — подвод элемента в зону видимости внутри прокручиваемого контейнера и прокрутка контейнера на величину. Зашитая в движке строка перечня API страницы (зеркало `.usages/facade.md`) обновляется синхронно — иначе модель не увидит новых возможностей.

## Scope

**In scope:**

- `ProductDefectError` — множественное наследование `AssertionError`; чистая поверхность отказа (ADR-1)
- Вердикт на каждом терминальном отказе: сообщение исключения + новое событие `StepHooks` + лог; тихий пропуск при LLM-недоступности (ADR-2)
- Остановка ретраев генерации при `AssertionError` кандидата с классификацией (ADR-3)
- Обновление текста классификационного промпта в `engine` (`classification_prompt`): с «падения кэшированного шага» на «падения шага» — под вызовы классификации с пути генерации (ADR-3); контракт ячейки `llm` не затрагивается
- `PrettyTest.get_screenshot()` и `PrettyTest.save_screenshot(filepath)` (ADR-4)
- Настройка `headless`; каналы `chrome`/`msedge`; переименование env `PRETTYPLAY_BROWSER_NAME` с подсказкой (ADR-5)
- Действенная ошибка конфигурации вместо сырого `pydantic.ValidationError` (ADR-6)
- Скроллы фасада страницы (страничные и контейнерные) + синхронное обновление строки перечня API страницы в движке (ADR-7)
- Обновление cell-level usage `driver/.usages/facade.md` под новую поверхность
- Тесты по конвенциям проекта (`pytest`, `ruff`)

**Out of scope:**

- «Крутить до появления» (бесконечные ленты) — отложено вне топика
- Автоскриншоты при терминальном падении шага — явно отклонено
- API скролла уровня основного объекта (`PrettyTest`) — не появляется; скролл — поверхность сгенерированного кода шагов
- Вердикт для `LlmUnavailableError` — инфраструктурный отказ, объяснением не снабжается
- Переименование TOML-ключа `browser` — переименована только env-переменная
- Плагины и интеграции раннеров — архитектурно исключено
- Изменения контракта `llm` — вердикт `FailureClassification` переиспользуется как есть

## Acceptance Criteria

- `isinstance`-проверка: `ProductDefectError` одновременно `PrettyplayError` и `AssertionError`; unittest и pytest показывают провал проверки как failure (не error); трейсбек сворачивается до библиотечной границы
- Каждый терминальный отказ `ProductDefectError`/`IncurableStepError` несёт вердикт (категория где применимо, объяснение, рекомендация) в сообщении исключения, в событии хуков и в логе; при недоступности LLM основной отказ не искажается и не задерживается, в логе WARNING
- На пути лечения `recommendation` доходит до `ProductDefectError`; при исчерпании лечения после rot вердикт не теряется
- Законно падающий assertion-шаг при первой генерации: ровно один провал проверки останавливает ретраи (не сжигает бюджет из 3 попыток), вызывается классификация, `product_defect` → `ProductDefectError` с объяснением; не-`AssertionError` ошибки кандидатов ретраиваются как раньше
- `get_screenshot()` возвращает full-page PNG-байты; `save_screenshot(filepath)` создаёт файл по указанному пути; автоскриншотов при падении нет
- `[tool.prettyplay] headless = false` запускает браузер с головой (env `PRETTYPLAY_BROWSER_HEADLESS`); `browser = "chrome"`/`"msedge"` запускает установленный браузер через channel; `PRETTYPLAY_BROWSER_NAME` действует, `PRETTYPLAY_BROWSER` не действует и даёт подсказку; невалидное значение настройки — действенная ошибка с именем настройки, значением и списком допустимых
- Сгенерированный код шагов может доскроллить: к элементу, на величину вниз/вверх, до конца/начала страницы, внутри контейнера (подвод элемента и прокрутка на величину); строка перечня API страницы в движке зеркальна обновлённому `facade.md`
- Обратная совместимость фасада: только расширение, без переименований и удалений; кэшированные шаги продолжают работать
- `ruff check` и `pytest tests/ -x` зелёные; Python 3.10+

## Risks and Constraints

- **Обратная совместимость фасада** — жёсткий контракт: только расширение `PageFacade`/`LocatorFacade`; кэшированный код шагов работает across releases
- **Синхронность двух копий поверхности**: строка перечня API страницы зашита в движке и зеркалит `driver/.usages/facade.md` — правятся только вместе
- **Множественное наследование** `ProductDefectError`: pytest и unittest по-разному репрезентуют исключения — проверка поведения на обоих раннерах
- **Типовое различение** `AssertionError` проверки от «элемент не найден» в ADR-3 опирается на реальную иерархию ошибок Playwright (`expect_*` против locator-таймаутов) — покрыть тестами на реальные типы, граница хрупкая
- **Каналы chrome/msedge** требуют локально установленного браузера — тесты каналов через `pytest.mark.skipif` при отсутствии браузера; при отсутствии — действенное сообщение
- **Переименование env** безопасно: внешних потребителей нет (факт discovery); подсказка при встрече старого имени
- Python 3.10+; конвенции проекта (`conventions`) обязательны

## Scope Estimate

Одна задача (решение пользователя). Масштаб: 7 ADR, 6 ячеек, ~10 типов — преимущественно точечные расширения. Разбиение отклонено: кластеры изменений (отказы+вердикты; настройки+браузер+скроллы; скриншоты) пересекаются по ячейкам `engine` и `driver`, отдельной ценности не несут — весь выпуск поставляется вместе в ветке `more-usability`. Следующая стадия (brainstorm) разнесёт контрактные правки по ячейкам.

## Existing Architecture

Затрагиваемые ячейки и характер изменений:

- `prettyplay/failures` — `ProductDefectError`: множественное наследование `AssertionError`, рендер сообщения с вердиктом (ADR-1, ADR-2)
- `prettyplay/llm` — контракт не меняется: `FailureClassification` переиспользуется; классификация начинает вызываться и с пути генерации (ADR-3)
- `prettyplay/engine` — `StepGenerator`: перехват `AssertionError` кандидата, стоп ретраев, классификация (ADR-3); вердикт на терминальных отказах (ADR-2); строка перечня API страницы (ADR-7)
- `prettyplay/reporting` — `StepHooks`/`StepReporter`: новое событие с вердиктом для отчётов интеграторов (ADR-2)
- `prettyplay/driver` — `DriverSession`: `launch(headless=..., channel=...)` (ADR-5); `PageFacade`: скроллы (ADR-7); `PageFacade.screenshot()` как основа скриншотов автора (ADR-4); обновление `.usages/facade.md`
- `prettyplay/config` — `Config`: поля `headless`, расширенный `browser`; `load_config`: env `PRETTYPLAY_BROWSER_NAME`, обёртка ValidationError (ADR-5, ADR-6)
- `prettyplay` (корневой фасад) — `PrettyTest`: `get_screenshot`/`save_screenshot` (ADR-4)
- `prettyplay/cache` — не затрагивается
